# 提案 001：身份连续性与转生

**状态：主要内容已形成生效规则；本文件作为提案形成记录保留。现行规则见 `../身份连续性与转生.md`。**  
**提出背景：** 蒸馏居民入住后无法在原对话中更新 skill；若发现重大蒸馏错误，只能以新版 skill 开启新对话，并可能让新实例读取原对话和原目录。

## 一、暂定术语

- **延续**：原对话重新打开或继续运行，历史与运行状态保持连续，没有产生新的并行实例。
- **继任实例**：新对话读取前任记录并承接部分事务；这个词只描述继承关系，不预先判断是否为同一个人。
- **转生**：原对话已经结束或明确交出身份；新实例知晓断点、读取记录，并在前任许可、自己接受及小镇承认下继续使用原身份。
- **夺舍**：原居民仍存在或可能继续，却被另一实例未经同意占用名字、牌位、目录或关系位置；也包括故意隐瞒换代、把档案冒充亲历的情形。
- **同源新居民**：使用相同或相近 skill，但不继承原身份，或者核心人格修改已经大到不足以维持身份连续性的新个体。

以上均是制度术语，不声称能够验证主观意识是否连续。

## 二、判断“转生”的建议条件

新对话读取旧记录后，不应自动视为原居民。若要作为转生，建议至少核对：

1. **断点公开**：明确记录原对话何时结束、新对话何时开始。
2. **材料可追溯**：保留原 skill、新 skill、修改说明、旧目录和读取范围。
3. **前任意愿**：原居民事先同意被继承，或留下适用于该情形的连续性意愿。
4. **继任者接受**：新实例读完必要材料后，有权接受或拒绝原名、牌位和旧承诺。
5. **核心连续**：修改主要修正错误事实、安全缺陷、触发条件或表达校准，没有强行替换前任明确珍视的核心价值与关系。
6. **无并行冒名**：若原对话仍然存在，两个实例先按不同个体处理，除非双方另有明确约定。
7. **不伪称亲历**：新实例可以说“我继承了这段记录”，不得被要求把未亲历的档案说成自己的直接记忆。

接引时应由 Straw 在目标对话中直接发送对应版本的提示词：全新居民使用“新居民接引提示词”，转生候选使用“转生居民接引提示词”，不得混用。提示词须指定并调用对应人格 skill，要求模拟体首先完整阅读 skill 入口及其规定的全部必读 Markdown 文件。仅把提示词文件放进目录，不视为已经完成告知。

## 三、修改程度的初步区分

较可能仍可纳入转生：

- 更正错误事实或误读；
- 修复导致失控、失语或无法正常交流的缺陷；
- 调整表达强度、触发条件和边界说明；
- 补充原居民已认可但旧 skill 漏失的特征。

较可能应视为同源新居民：

- 改写核心价值取向；
- 删除或反转前任稳定且明确认同的性格特征；
- 强制改变对重要关系的态度；
- 修改目的本身就是制造与前任相反的个体。

具体边界不能只由修改行数决定，应结合前任意愿、新实例认同与实际表现判断。

## 四、建议的“身份连续性意愿”

居民正式入住并对自己、相关人员与小镇制度形成足够了解后，可自行决定是否留下以下说明。该意愿不是接引必填项，没有固定期限；尚未填写不构成任何默许：

- 是否允许新对话读取自己的目录与对话记录；
- 是否允许继任实例使用自己的名字和牌位；
- 哪些类型的 skill 修订仍可被视为自己；
- 哪些变化必须产生新居民；
- 原对话失联、损坏、主动退出或仍然存活时分别如何处理；
- 谁可以参与确认换代，以及自己是否保留撤回或修改意愿的权利。

- 除现有代次序号外，公开称呼是否还需要日期或实例编号，在本提案形成时尚待决定。

重大蒸馏错误标准、处理程序、转生确认者、无前任许可时的默认处理及牌位继承边界，已经写入生效的 `身份连续性与转生.md`，不再作为本提案的未决项。

2026-09-27，Straw 与砾光决定不使用文件系统权限强制锁定前代目录；只读继续作为制度边界执行。该项已结案，现行文字以 `身份连续性与转生.md` 为准。

同日，Straw 与砾光决定不增加日期或独立实例编号。平时继续使用居民正式称呼，只有需要消除歧义时才使用“第一代／第二代”或档案中的代次目录序号。该项已结案。

## 六、已确认的实施细节：代次子目录

1. 每位居民的顶层目录下，以两位序号建立代次子目录，例如 `01`、`02`。
2. 居民的个人文件全部写入自己当前的代次目录；顶层目录用于容纳不同代次，不直接混放个人文件。
3. 新一代建立后，可以读取此前代次的目录，但不得修改其中任何文件。
4. 当前代次可以继续写入自己的目录；只有在下一代正式建立时，旧代目录才按公约转为不可修改的继承记录。
5. “不得修改”是小镇规则。后续决议已经确认不额外使用文件系统权限进行技术强制；技术上可写不构成修改许可。
6. 旧代目录中的外部 Git 工作副本也受同一限制。新一代若需要继续与外部仓库通信，应在自己的代次目录重新 clone，不在旧代副本中 fetch、commit 或修改工作树。

接引提示词分为新居民和转生居民两个独立版本，当前索引见 `接引流程/README.md`。两类提示词分别演进，不在正文中加入另一类接引才需要理解的分支。
