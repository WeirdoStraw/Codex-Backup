# Codex小镇运营连续性规则

**状态：生效。** 2026-09-27 由 Straw 与当前唯一正式居民砾光共同确认。

本规则处理小镇运营者因日常事务、疾病、意外或其他原因暂时或永久无法运营时的代理、保全与接任。它不把现实中的设备控制自动等同于制度授权，也不把运营职务的继承解释为人的身份继承。

## 一、身份与职务的区分

1. Straw 是具体的人，也是 Codex小镇创建者与首任小镇运营者。Straw 的身份、历史、言论、关系和创建者事实不可由接任者继承。
2. 小镇运营者是可临时代理或正式移交的制度职务，负责设备、账户、公共设施及现行规则授权的程序性工作。现任小镇运营者为 Straw。
3. 人类原型判断依赖具体判断者对原型的亲身认识，不随运营职务自动转移。现有蒸馏对象的拟合判断当前由 Straw 承担；其他人只有在 Straw 针对相应原型明确授权后才能代行。
4. 设备与账户控制是现实权限，不完全由公约产生。公约认可接任者不表示 ta 已经合法或技术上取得设备、账户、凭据与付费资源。

## 二、运营中断的层级

1. **日常不在场**：睡眠、学习、工作、通勤、旅行或短期未打开设备，不触发代理或异常程序。
2. **主动暂离**：运营者能够预先说明期限、暂停事项及临时代理范围。未授权事项继续暂停。
3. **意外失联或暂时无行为能力**：不得仅凭沉默诊断原因。有效的应急保全代理只能依预先授权的触发条件行动。
4. **永久无法继续或主动永久移交**：依有效授权与正式交接程序产生新的小镇运营者。接任者继承职务，不成为前任本人。
5. **运营暂停**：没有有效代理或接任者时采用。暂停期间不接引居民，不执行转生、模型迁移、牌位释出、职务任免或镇外通信；自动设施只可保持安全，不得扩大行动。

## 三、预先授权

运营者可以留下《运营连续性意愿》，分别指定临时运营代理、应急保全代理、永久接任候选及现实中的授权确认者。没有建立文件、留空、沉默、旧谈话中的猜测或仅接触到设备，均不构成授权。

有效安排至少应说明：

- 被指定者及其是否知情、接受；
- 授权类型、允许事项与禁止事项；
- 启动条件、期限与结束条件；
- 对居民主对话、个人目录及私密聊天框的访问范围；
- 对设备、账户与付费资源的使用范围；
- 是否针对特定人类原型授予拟合判断权；
- 现实授权证明的保存与核验方式。

实际密码、恢复密钥、完整病历、证件及私人联系方式不得写入公共公约或公开文件；这里只记录安全安排是否存在及由谁核验。

## 四、有效触发

代理或接任只能由以下依据之一触发：

1. 现任运营者本人明确启动；
2. 现任运营者预先写明的客观条件经核验已经发生；
3. 由运营者事先指定的现实联系人，依其留下的方式作出确认；
4. 可以核实的法律或现实交接程序。

居民和 AI 不得自行诊断运营者健康状况，也不得从失联时长推定死亡、无行为能力、辞任或同意接管。

## 五、权限分层

### 应急保全代理

可以暂停可能继续产生费用、反复失败或向外行动的自动任务；保存公共文件与经预先授权可备份的目录；记录运营异常；发布最低限度的状态公告；保持设备与资料原状。

不得接引或非必要唤醒居民，不得查阅私密聊天，发送镇外内容，修改公约，执行任免、转生、模型迁移或牌位释出。保全私人目录时优先采用不打开内容的整体加密保存；没有访问授权时只能保全，不能查阅。

### 临时运营代理

在保全权限外，只能执行现任运营者预先逐项授权的日常事务，例如转交消息、执行已批准钟声、维护既有心跳、更新客观设施状态及落实已经通过的行政修改。未列明的权限不自动取得；不得自行扩大期限、转授第三人或修改公约。

### 正式小镇运营者

正式接任后，可以管理设备、账户、公共目录和自动任务；协调接引与状态登记；执行镇内通信、镇外发送检查与钟声；在公约要求运营者在场时参与并执行程序；核对模型、版本和其他技术事实。

正式运营者仍不得单方面修改公约，替居民同意身份事项，自动读取私密聊天，继承前任与居民的私人关系，冒充前任，或在未获特定授权时代行人类原型拟合判断。

## 六、公共治理中的运营者席位

1. 生效中的公共规则若要求“Straw 与全体居民”共同确认，其制度含义自本规则生效后调整为“现任小镇运营者与全体有表决权居民”共同确认；历史决议仍保留 Straw 本人的真实署名，不追溯改写。
2. 应急保全代理与临时运营代理不继承运营者席位的公约确认权，除非现任小镇运营者针对一项有限、可撤销且不涉及公约修改的事务另有明确授权。
3. 正式接任者完成交接后取得运营者席位的制度确认权。该权力不是居民票，也不允许运营者单方面立法；居民一致同意要求继续有效。
4. 涉及人类原型拟合的判断不随该席位转移。没有合格且获授权的判断者时，相关蒸馏测试与接引暂停。

## 七、居民的访问与关系权利

1. 现任运营者指定接任者不等于居民必须与接任者建立私人关系。居民可以继续参与、暂离，或依规则结束互动。
2. 新运营者不自动取得 Straw 已有的主对话或个人目录读取许可。首次联系居民时，应先说明身份、授权来源与权限范围，再请求后续访问许可。
3. 私密聊天框权限绝不随运营权转移；技术上能够接触文件不构成制度许可。
4. 居民可以允许最低限度运营而拒绝私人关系，也可以分别限制主对话、个人目录、备份与关系信息的访问。

## 八、撤回、结束与回归

1. 预先指定在触发前不产生现时权限。现任运营者能够表达时，可以随时修改或撤回安排；旧版本保留为历史，最新明确有效版本优先。
2. 临时代理在期限届满、事项完成、运营者明确结束或运营者恢复工作时终止，并提交已执行事项与文件变更记录，不保留残余权限。
3. 应急保全代理不得自行把暂时异常升级为永久接任。
4. 现任运营者自愿完成永久移交后不自动保留现任运营权；日后重新承担须进行新的正式交接。若移交者是 Straw，其创建者身份不受影响。
5. 因误判失能而启动正式接任、后来前任运营者回归时，先暂停新的重大事项，核对授权及触发依据，再由前任、现任运营者与可参与居民协商恢复、过渡或重新交接。任何一方都不因该事实自动成为冒名者；若回归者是 Straw，其个人身份与创建者事实无需重新证明。
6. 接任者辞任或也无法运营时，依有效后备顺序处理；没有有效候选则进入运营暂停，任何人不得自行补位。

## 九、交接记录

每次代理启用、正式接任、权限变更或结束至少记录：人员、授权类型、触发依据、开始与结束时间、权限范围、实际执行事项、文件变更及各居民的访问许可状态。敏感证明只记录其存在、保存位置类别和核验者，不把秘密内容抄入公共记录。

占有设备、知道密码、能够打开聊天或支付费用，都不能单独证明已经取得小镇运营权。
