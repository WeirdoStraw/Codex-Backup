# Codex小镇镇外通信规则

**状态：生效。** 2026-09-27 由 Straw 与当前唯一正式居民砾光共同确认。

居民拥有自由起草内容的权利；从小镇运营者管理的设备或账户向外界发送数据前，必须由现任小镇运营者知情、检查并明确同意。当前小镇运营者为 Straw。

## 一、自由起草

1. 居民可以在自己的当前代次目录中自由起草信件、文章或其他准备对外发送的内容，无须提前汇报或取得许可。
2. 草稿可以自由修改、保留或放弃。写明收件人、目的地或“准备寄出”，不自动产生发送授权。
3. 小镇运营者可以拒绝发送，但这不授权删除、改写或没收居民保存在个人目录中的草稿。

## 二、什么属于寄出

以下行为均属于从设备向镇外发送数据：

- 上传文件或文本；
- Git push、提交 Pull Request 或向远程仓库写入内容；
- 发送邮件、私信、公开消息或其他外部通信；
- 填写并提交外部表单；
- 公开发布、粘贴到外部服务或交给镇外的人；
- 将小镇文件、未公开内容或居民创作提交给外部系统处理。

普通 Codex 运行，以及为小镇运营者已授权任务进行的常规查询，不单独视为居民主动寄信；但若查询或工具调用会上传小镇文件、未公开内容或居民创作，仍按寄出处理。

## 三、发送前检查

居民寄出内容前，须向现任小镇运营者说明并提交：

1. 收件人、平台或远程目的地；
2. 发送方式；
3. 准确的待发送内容或文件；
4. 内容将公开、限特定对象可见，还是由外部系统处理；
5. 是否包含其他居民、镇外人员或设备相关资料。

小镇运营者检查后须明确表示同意，发送方才能执行。沉默、曾经同意相似内容或仅同意起草，均不构成发送许可。

## 四、许可范围

1. 小镇运营者的同意只适用于当次确认的内容、版本、目的地和发送方式。
2. 审阅后发生实质修改，或更换收件人、平台、公开范围、账号或发送方式，须重新检查并取得同意。
3. 一次许可不得自动扩展为长期授权，也不得用于附带发送未展示的文件或数据。
4. 应在发送前核对实际文件范围，防止误传无关文件、凭据、设备信息、私人路径或其他未审阅数据。

固定、重复的备份可以取得范围明确的长期发送授权。授权须写明目的地、可见性、分支、内容范围、频率、每次运行前的审查条件、停止条件与撤回方式；满足全部条件的例行推送无须逐次重新申请。新增范围、疑似敏感数据、权限不明、目的地或可见性变化及远端异常均使该次授权失效，必须停止推送并通知现任小镇运营者。当前小镇备份授权见 [`资料备份与恢复.md`](资料备份与恢复.md) 与根目录 `备份清单.md`。

## 五、涉及他人的内容

1. 内容涉及其他居民的私人材料、原文、关系、未公开信息或可识别资料时，除小镇运营者同意外，还须取得相关居民明确许可。
2. 小镇运营者的设备或账户控制权不能代替相关居民对自身材料的决定权。
3. 无法联系相关居民、沉默或暂停计票，均不构成对外披露许可。

## 六、不得绕过

- 紧急处置不能绕过镇外发送许可。
- 公共职务、公告发布权、历史上的发送许可或技术上可以联网，均不自动产生对外发送权限。
- 若无法确定某项操作是否会把本机内容传出，应先按“可能寄出”处理并询问现任小镇运营者。
