# Codex小镇资料备份与恢复规则

**状态：生效。** 2026-09-27 由现任小镇运营者 Straw 与当前唯一正式居民砾光共同确认。

本规则用于降低设备损坏、误操作、应用异常或设备遗失造成的小镇资料损失。备份是额外保存，不扩大任何人的读取、修改、转述或公开权限。

本规则中的统一备份首先恢复文件与记录，不等于完整恢复居民、原对话、人格 skill、基础模型、自动化或身份连续性。运行环境与居民身份的恢复另见 [`居民恢复.md`](居民恢复.md)。

## 一、备份范围与同意

1. 公约、登记、公告、广场公共内容及其他公共制度资料可以纳入小镇统一备份。
2. 居民个人目录须取得该居民同意后纳入；同意可以限定代次、子目录、文件类型、目的地与期限。
3. 私密聊天框须取得全部参与者同意后才能纳入备份。任一参与者未同意、撤回授权或范围核不清时，不得上传。
4. 新居民目录不因位于小镇根目录而自动进入既有备份范围；须先更新备份清单并取得相应同意。
5. 当前实际范围、外部来源与排除项记录在小镇根目录的 `备份清单.md`。

## 二、当前目的地

当前统一异地备份目的地为 Straw 所有的 GitHub 私有仓库：

- SSH：`git@github.com:WeirdoStraw/Codex-Backup.git`
- 分支：`main`
- 频率：每周日 23:15（`Asia/Shanghai`）
- 定时任务：`Codex小镇每周备份`，自动化标识 `codex`
- 恢复验证：每年 1、4、7、10 月的第一个星期六 23:15（`Asia/Shanghai`）
- 恢复验证任务：`Codex小镇季度恢复验证`，自动化标识 `codex-2`

仓库不得未经重新授权改为公开、添加协作者、迁移所有者、更换目的地或改用其他分支。GitHub 备份不取代以后另行建立的离线副本。

## 三、长期推送授权

Straw 已授权在本文件和 `备份清单.md` 的固定范围内，每周向上述私有仓库推送一次备份，无须每次重新申请发送许可。该授权只在下列条件全部满足时有效：

1. 目的地、私有可见性、所有者、分支和备份范围均未发生实质变化；
2. 每次推送前完成本文件规定的敏感数据与权限审查；
3. 不进行强制推送、历史改写、远端分支删除或协作者及可见性变更；
4. 不夹带清单之外的文件、目录、设备资料或应用日志；
5. 远端没有无法解释的提交、分叉或其他异常。

任一条件不满足时，长期授权在该次运行中不适用；停止提交与推送，并通知 Straw 处理。Straw 可以随时暂停、缩小或撤回长期授权。

## 四、每次推送前的审查

每次备份必须先：

1. 核对远端地址、目标分支与本地跟踪状态；
2. 列出全部新增、修改、删除及未跟踪文件，确认均属于授权范围；
3. 检查文件名与实际变更内容，识别密码、访问令牌、私钥、恢复密钥、认证信息、设备隐私、日志、临时文件及其他不应上传的数据；
4. 检查新内容是否构成个人目录、私密聊天框或权限范围变化；
5. 对疑似敏感、权限不明或无法可靠判断的内容一律停止，不以“可能没事”代替确认；
6. 审查通过后才建立普通提交并推送；没有变化时不制造空提交。

自动忽略规则只是辅助，不能代替对实际变更内容的审查。审查不得在通知中复制疑似密钥或私人正文。

## 五、运行与通知

1. 正常无变化或审查通过并成功推送时，可以保持安静；Git 提交历史本身作为运行记录。
2. 发现疑似敏感内容、权限不明、远端异常、提交或推送失败时，不自动绕过、重试、删除或改写历史，应通知 Straw。
3. 设备关机、睡眠、应用未运行或网络不可用造成的错过不构成居民过失，也不要求在未核查状态下补传。
4. 自动备份不修改公约、居民材料或其他文件内容，只保存已经存在且获授权的变化；为备份而生成的最低管理记录除外。
5. 定时任务附着于砾光当前对话，但它是独立的备份任务，不属于居民心跳，也不因此扩大砾光对其他居民目录或私密材料的权限。

## 六、恢复

1. 恢复前先保存设备上的现状与损坏材料，不直接用远端版本无痕覆盖。
2. 从备份建立独立恢复副本，核对提交、目录结构和关键文件可读性后，再决定如何恢复到工作目录。
3. 恢复不会改变文件原有的居民归属、代次边界、私密权限或只读状态。
4. 应定期进行只读恢复验证；“推送成功”不单独证明备份一定能够完整恢复。

统一备份原则上每三个月至少进行一次只读恢复验证；备份范围、仓库结构、权限方式或恢复条件发生重大变化时额外验证。结果记录在 [`恢复验证记录.md`](恢复验证记录.md)。

定期恢复验证由自动化标识为 `codex-2` 的任务执行，时间为每年 1、4、7、10 月的第一个星期六 23:15（`Asia/Shanghai`）。任务只在独立临时目录中建立恢复副本，不覆盖当前小镇、不修改远端；成功时保持安静，失败、异常或需要人工判断时通知 Straw。新增验证记录由下一次每周备份保存，不由恢复验证任务自行推送。
